# Quickstart: Сайт бара с меню и клиентским кабинетом

**Feature**: [spec.md](./spec.md) | **Plan**: [plan.md](./plan.md) | **Data model**: [data-model.md](./data-model.md) | **Contracts**: [contracts/api.md](./contracts/api.md)

## Предварительные требования

- Node.js LTS (20+)
- PostgreSQL 15+ (локально или в Docker)
- Telegram-бот через @BotFather (`TELEGRAM_BOT_TOKEN`, `NEXT_PUBLIC_TELEGRAM_BOT_USERNAME`) — единственный способ входа, по deep link `t.me/<bot>?start=<token>` (FR-004). Без `NEXT_PUBLIC_TELEGRAM_BOT_USERNAME` кнопка Telegram-входа показывает заглушку («Telegram ще не налаштований»); без публичного HTTPS-домена (или ngrok) и настроенного `npm run telegram:set-webhook` подтверждение входа от бота не дойдёт и войти в кабинет/админку локально не получится.

## Настройка

```bash
npm install
cp .env.example .env   # DATABASE_URL, NEXTAUTH_SECRET, TELEGRAM_BOT_TOKEN, NEXT_PUBLIC_TELEGRAM_BOT_USERNAME
npx prisma migrate dev
npx prisma db seed      # тестовые категории/позиции меню, баннер акции, SiteContent
```

## Запуск

```bash
npm run dev
```

Сайт: `http://localhost:3000`.

## Проверка сценариев (по User Stories из spec.md)

### User Story 1 — Меню (P1)

1. Открыть `/menu` без входа в аккаунт.
2. Убедиться, что видны категории верхнего уровня и подкатегории (FR-001).
3. Открыть подкатегорию — позиции показывают фото, название, цену, объём (и крепость для алкоголя) (FR-002).
4. Ввести запрос в поиск — список фильтруется (FR-019); запрос без совпадений → пустой результат с сообщением «Ничего не найдено».
5. Нажать лайк на позиции — счётчик +1; повторный клик — счётчик возвращается (toggle) (FR-020).
6. Открыть `/menu/popular` — позиции отсортированы по лайкам (FR-021).

**Ожидаемый результат**: все действия выполняются без регистрации/входа (FR-003).

### User Story 2 — Регистрация и личный кабинет (P2)

1. Войти через Telegram-бота на `/login` (кнопка открывает `t.me/<bot>?start=<token>` в приложении Telegram) — аккаунт создаётся автоматически при первом входе (FR-004).
2. Войти повторно тем же Telegram-аккаунтом → возвращает тот же `User` (по `telegramId`), не создаёт дубликат.
3. Первый вход в `/account` показывает приветственное поздравление, «Мои чеки» пусты (FR-016).
4. (Через seed или ручную вставку в БД) добавить пользователю чек с позициями → в `/account/receipts` отображается чек с полным составом (FR-007); должно быть создано соответствующее `BonusTransaction`.
5. Открыть `/account/bonuses` → виден баланс (сумма транзакций, «0 ₴» при отсутствии) и история операций (FR-010).
6. Изменить имя/email/телефон в `/account/profile` (FR-024); попробовать указать email/телефон, уже занятый другим аккаунтом → ошибка «Пользователь уже зарегистрирован» (FR-017).
7. Выйти из аккаунта и попытаться открыть `/account/*` → редирект на вход (FR-006).
8. На любой странице проверить карусель акций в хедере — свайп/стрелки переключают баннеры (FR-008); при одном активном баннере переключение недоступно.

### User Story 3 — Контакты и о заведении (P3)

1. На `/menu` убедиться, что в постоянном виджете рядом с меню видны адрес (кликабелен → Google Карты) и часы работы (единый диапазон, без статуса «открыто/закрыто») (FR-013, FR-023).
2. В футере/блоке контактов — кликабельный телефон («позвонить»), ссылки на соцсети, встроенная карта (FR-012, FR-013).
3. На `/` (главная) — блок с описанием концепции заведения (FR-014) и дисклеймер об аллергии виден в разделе меню/еды (FR-022).

## Тестирование

- Unit/интеграционные тесты — Vitest (или Jest) для сервисных функций (расчёт бонусов, toggle лайка, валидация уникальности email/телефона).
- Контрактные тесты API — по эндпоинтам из `contracts/api.md` (например, через supertest/Next.js route handler тестирование).
- E2E — Playwright, сценарии выше как основа тест-кейсов.
